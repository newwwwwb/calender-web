# 00 Brief — 차계부

- 날짜: 2026-11-05
- 소유자: Product Owner
- 요구 원본: [docs/superpowers/specs/2026-11-05-carbook-design.md](superpowers/specs/2026-11-05-carbook-design.md) (사용자 승인, 커밋 88b3f15). 이 문서와 다르면 원본을 따른다.

## 한 줄 목표
로그인한 사용자가 지금 캘린더 웹 안에서 자기 차량의 주유·정비·지출 기록, 소모품 교체 시기, 만기일(보험·자동차세·정기검사), 지출 통계를 한곳에서 관리하고, 교체일과 만기일은 캘린더 일정으로도 본다.

## 사용자 문제
- 주유·정비 지출이 영수증, 메모, 별도 앱에 흩어져 월 지출과 연비를 알기 어렵다.
- 엔진오일·필터 교체 시기와 보험·세금·검사 만기를 잊는다. 이미 쓰는 캘린더에 이 날짜가 보이지 않는다.

## 대상 사용자
- 이 캘린더 웹에 로그인한 본인. 차량 1대 이상. 공유하지 않는다.

## 제약
- 기존 캘린더 화면 배치·동작과 캘린더 코드(`useCalendar`, 화면 컴포넌트)를 바꾸지 않는다(원본 AC-2).
- 라우터 라이브러리를 추가하지 않는다. `App.tsx`의 기존 주소 분기(`matchShareId`) 방식으로 `/car`를 연다.
- 데이터는 Supabase. 새 테이블 4개는 `supabase/schema_carbook.sql`에만 두고 기존 스키마 파일은 고치지 않는다. 모든 행은 RLS(`auth.uid() = user_id`).
- 로그인하지 않으면 차계부를 쓸 수 없다(로컬 저장 없음).
- 범위 밖: 푸시 알림, 번호판 자동 조회, 영수증 사진, 예약, 차량 공유, 로컬 모드 저장.

## 기한
- 사용자가 지정하지 않았다(열린 질문으로 두지 않는다. 마일스톤은 PRD에서 제안).

## 사용자가 지정한 스택
- 지금 저장소 스택 그대로: React 19, TypeScript, Vite, Supabase(`@supabase/supabase-js`), date-fns, vitest + Testing Library, oxlint. 새 의존성 없음.

### 기술 (Tech Researcher)
- T-1. 라우터 라이브러리 없이 `App.tsx`의 `matchShareId` 방식으로 `/car` 주소와 뒤로·앞으로 가기(History API `popstate`)를 처리할 때 주의점과, 지금 배포 호스팅에서 `/car` 새로고침이 index.html로 연결되는지(SPA 폴백 설정)?
- T-2. 기존 `events`·`categories` 테이블의 컬럼과 RLS를 기준으로, 차계부가 Supabase 클라이언트로 종일 일정을 직접 만들고·고치고·지울 때 캘린더 화면이 새 일정을 반영하는 방식(실시간 구독, 다시 불러오기)과 충돌 위험은?
