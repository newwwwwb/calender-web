# v0.1.0 회고 (차계부)

- 릴리스: 2026-11-21, 태그 v0.1.0(30ad92b), 사용자 Promote, 배포 후 확인 정상. 롤백 대상 87f6f44.

- 규모: 스토리 16, 기술 티켓 MPR-17~48, AC 122개 모두 티켓에 연결, 전체 테스트 97 files 1129 passed(RC에서 1회).

## 잘된 것

1. 설계서를 요구 원본으로 고정하고 사용자 질문을 2번으로 줄였다(OQ-1 공유 숨김, Overlay 예외). 기획 검토 2회차에 Major 0으로 통과했다. 근거 docs/01_prd.md 변경 기록, docs/review/plan-review.md.
2. 기술 티켓이 AC를 모두 덮어 구현 중 구조 질문이 없었다. 배포 전 설계 보완으로 보안 결함 둘(MPR-42, MPR-43)을 막았다. 근거 docs/02_architecture.md 12장.
3. 검증이 작성자 보고에 기대지 않았다. 리뷰어는 토큰을 값으로 되돌려 변경 0을 직접 확인했고(MPR-45), QA는 실앱을 모의 Supabase에 물려 겹친 창 Esc·Tab과 삭제 뒤 포커스 결함을 잡았다(MPR-33, 46b). 근거 docs/qa/report.md.
4. 병합마다 브랜치 머리가 리뷰한 커밋과 같은지 확인했고(MPR-39), 스택 브랜치 병합 순서를 요청에 적어 충돌 0으로 끝났다. 운영 확인은 데이터 변경 없이 anon 점검과 SQL Editor 가장 점검으로 했다(MPR-48).

## 문제

1. 불변 파일 제약 충돌을 늦게 발견했다. "캘린더 코드 0줄 변경"과 필요한 `Overlay.tsx` 수정(c4e4a6b)이 리뷰가 아니라 마지막 QA(MPR-38)에서 드러났고 사용자 결정까지 약 3일 걸렸다. 예외 승인 권한자를 확인하기 전에 결정이라고 보냈다가 정정하기도 했다(306a152, 0f5ba15). 근거 docs/qa/report.md 704~706행.
2. AC 추가에 스토리·기술 티켓 매핑이 뒤따라가지 못했다. AC가 116에서 123개로 늘 때마다 PO·Architect 왕복이 5번 생겼고 AC-05-7은 스토리에서 12일 빠져 있었다.
3. 티켓을 a~j로 잘게 쪼개 병합과 QA 요청이 수십 번으로 늘고, 전체 테스트를 매번 돌려 불안정 테스트가 반복됐다. 결정 8e44ae(변경 범위만 테스트, 쪼개기 중단)로 줄였다.
4. 운영이 마지막 Production 87f6f44(2026-10-08) 이후 약 260커밋을 한 번에 받았다. 성능 AC(AC-04-9, 04-10)는 모의 서버로만 재서 실제 Supabase 지연은 측정하지 못했다.
5. 시간 의존 동작(포커스·타이머·aria-live)을 코드 대조 없이 승인하거나 Nit로 낮춰 Auditor가 다시 올렸다(MPR-33, 36, 46). 리뷰 요청 1건이 리뷰어 인박스에 도착하지 않았다(MPR-39).

## 다음에 바꿀 것 (1개)

"불변 파일 제약(예: 캘린더 0줄 변경)은 티켓 시작 때 파일 목록으로 대조하고 병합마다 `git diff --stat`으로 확인한다. 제약에 걸리는 수정이 필요하면 구현 전에 Software Architect가 god을 거쳐 사용자 승인을 받는다." 담당은 Software Architect(체크리스트)와 Code Reviewer(병합마다 확인).
