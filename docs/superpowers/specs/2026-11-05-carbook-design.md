# 차계부(차량 유지비 기록) 설계

- 날짜: 2026-11-05
- 상태: 사용자 검토 대기
- 참고 앱: 마이클(기능만 참고, 화면과 디자인은 이 캘린더 웹 스타일을 따른다)

## 1. 목적과 합의한 이해

| 구분 | 내용 |
|---|---|
| 목표 | 지금 캘린더 웹에 차계부를 붙인다. 주유, 정비·지출 기록, 소모품 교체 알림, 만기일 알림, 지출 통계를 한곳에서 관리한다. |
| 사용자 | 로그인한 본인. 차량은 여러 대 등록할 수 있고 본인이 등록한 차량만 본다. 공유는 하지 않는다. |
| 화면 원칙 | 기존 캘린더 화면 배치와 동작은 바꾸지 않는다. 파일철 탭을 눌러 차계부 페이지로 이동한다. |
| 캘린더 연동 | 소모품 다음 교체일과 만기일(보험, 자동차세, 정기검사)만 캘린더에 일정으로 보인다. 주유·정비 기록은 차계부 안에만 둔다. |
| 성공 기준 | 아래 '수락 기준'을 모두 통과하고, 기존 캘린더 테스트가 그대로 통과한다. |

## 2. 접근 방식 (선택: A)

- **A. 별도 모듈 + 캘린더에는 일반 일정으로 넣기 (선택)**: `src/carbook/` 독립 모듈, `/car` 주소. 교체일과 만기일은 차계부가 '차계부' 카테고리의 일반 일정을 기존 `events` 테이블에 만들고 고친다. 캘린더 코드를 바꾸지 않는다.
- B. 캘린더가 차계부 데이터를 직접 읽어 표시: 캘린더 화면 코드를 고쳐야 해서 탈락.
- C. 별도 웹 + iCal 구독: 로그인, 배포, 알림을 새로 만들어야 해서 탈락.

## 3. 화면과 이동

### 3.1 파일철 탭
- 화면 오른쪽 가장자리에 세로 탭 두 개("캘린더", "차계부")를 고정한다.
- 현재 화면의 탭이 앞으로 튀어나와 보인다(파일철 색인 탭 모양).
- 기존 캘린더 레이아웃 위에 겹쳐 놓고, 캘린더 요소의 크기와 위치는 바꾸지 않는다.

### 3.2 주소
- `/`: 지금 캘린더 (변경 없음)
- `/car`: 차계부
- `/share/<id>`: 지금 공유 수락 (변경 없음)
- 새로고침, 뒤로가기, 앞으로가기가 동작한다. 라우터 라이브러리는 추가하지 않고 `App.tsx`의 기존 주소 분기 방식(`matchShareId`)을 따른다.

### 3.3 차계부 화면 구성
1. 상단: 차량 선택(여러 대), 차량 추가 버튼, 차량 정보 카드(차종, 연식, 번호판, 현재 주행거리)
2. 하위 탭 네 개
   - **기록**: 주유와 정비·지출 기록을 날짜 내림차순으로 보여 준다. 추가, 수정, 삭제할 수 있다.
   - **교체 알림**: 항목별 교체 주기(km, 개월 또는 둘 다)와 다음 교체 예정일. 처음 차량을 등록하면 내장 추천 주기로 항목을 채운다. 사용자가 주기를 고치거나 항목을 더하고 뺄 수 있다.
   - **만기일**: 보험 만기, 자동차세 납부, 정기검사 날짜
   - **통계**: 월별 지출 합계, 항목별 지출 합계, 연비 변화

### 3.4 로컬 모드(로그인 안 함)
- 차계부 탭을 누르면 "로그인하면 사용할 수 있습니다"와 로그인 버튼을 보여 준다. 로컬 저장은 지원하지 않는다.

## 4. 데이터

모든 테이블은 `user_id uuid not null references auth.users(id) on delete cascade`를 갖고, RLS로 `auth.uid() = user_id`인 행만 select, insert, update, delete할 수 있다. 차량에 딸린 행은 `vehicle_id ... on delete cascade`로 차량과 함께 지워진다.

| 테이블 | 주요 컬럼 |
|---|---|
| `vehicles` | id, user_id, name(별칭), model(차종), year(연식), plate(번호판), odometer_km(현재 주행거리), created_at |
| `car_records` | id, user_id, vehicle_id, kind(`fuel`, `maintenance`, `wash`, `insurance`, `tax`, `parking`, `other`), date, amount_won, odometer_km(선택), liters(주유만), full_tank(주유만, bool), memo, created_at |
| `car_maintenance_items` | id, user_id, vehicle_id, name, interval_km(선택), interval_months(선택), last_date, last_odometer_km, event_id(연결된 캘린더 일정, 선택), created_at. `interval_km`와 `interval_months` 중 하나 이상 필수(check 제약) |
| `car_due_dates` | id, user_id, vehicle_id, kind(`insurance`, `car_tax`, `inspection`), due_date, event_id(선택), created_at |

마이그레이션 파일: `supabase/schema_carbook.sql` (기존 파일은 고치지 않는다).

### 4.1 내장 추천 교체 주기 (처음 등록할 때 채우는 기본값, 사용자가 바꿀 수 있음)

| 항목 | km | 개월 |
|---|---|---|
| 엔진오일 | 10,000 | 12 |
| 에어컨 필터 | 10,000 | 6 |
| 에어 필터 | 20,000 | 12 |
| 타이어 위치 교환 | 10,000 | - |
| 브레이크 패드 점검 | 20,000 | - |
| 와이퍼 | - | 12 |
| 배터리 점검 | - | 36 |

## 5. 계산 규칙

- **다음 교체일**
  - 개월 주기: `last_date + interval_months`
  - km 주기: 남은 거리(`last_odometer_km + interval_km - 현재 주행거리`)를 하루 평균 주행거리로 나눈 날 수를 오늘에 더한다.
  - 하루 평균 주행거리: 그 차량의 주행거리가 적힌 기록 중 최근 90일 안의 가장 이른 기록과 가장 늦은 기록의 차이를 날 수로 나눈다. 기록이 2개 미만이면 km 주기는 날짜로 바꾸지 않고 "주행거리 기록 부족"으로 표시한다.
  - 둘 다 있으면 더 이른 날을 쓴다.
- **곧 교체 표시**: 다음 교체일이 오늘부터 30일 이내이거나 남은 거리가 1,000km 이하이면 붙인다. 이미 지났으면 "교체 시기 지남"으로 표시한다.
- **현재 주행거리**: 차량의 `odometer_km`와 기록의 최대 `odometer_km` 중 큰 값.
- **연비(km/L)**: 가득 주유 기록(`full_tank = true`) 두 개가 연달아 있을 때, 두 기록의 주행거리 차이 ÷ 첫 가득 주유 다음부터 두 번째 가득 주유까지(두 번째 포함) 넣은 모든 주유 기록의 주유량 합계. 가득 주유 기록이 2개 미만이거나 둘 중 주행거리가 없으면 표시하지 않는다.
- **통계**: 선택한 차량의 `car_records.amount_won`를 월별, 종류별로 더한다.

## 6. 캘린더 연동

- 차계부를 처음 쓸 때 사용자 소유의 '차계부' 카테고리를 한 번 만든다. 이미 있으면 그것을 쓴다(이름으로 찾는다).
- 교체 항목이나 만기일을 저장하면 그 카테고리로 종일 일정 하나를 만들거나(`event_id`가 없을 때) 고친다(있을 때).
  - 제목 예: `[내 차] 엔진오일 교체 예정`, `[내 차] 보험 만기` (`내 차` 자리는 차량 별칭)
  - 날짜: 계산한 다음 교체일 또는 만기일
- 다음 교체일을 계산할 수 없으면(주행거리 기록 부족) 일정을 만들지 않는다.
- 차계부를 열 때 연결된 `event_id`가 `events`에 없으면 일정을 다시 만든다.
- 교체 항목이나 만기일, 차량을 지우면 연결된 일정도 지운다.
- 캘린더 코드(`useCalendar`, 화면 컴포넌트)는 고치지 않는다. 차계부는 `events`, `categories` 테이블에 Supabase 클라이언트로 직접 쓴다.
- 날짜가 되면 울리는 푸시 알림은 없다. 지금 캘린더에도 없고 이번 범위 밖이다.

## 7. 오류 처리

- 저장에 실패하면 기존 토스트(`useToast`)로 "저장하지 못했습니다. 다시 시도해 주세요"를 띄우고 입력값을 지우지 않는다.
- 기록은 저장됐지만 캘린더 일정 반영에 실패하면 기록은 유지하고, 그 항목에 "캘린더 반영 실패, 다시 시도" 버튼을 보여 준다.
- 입력 검사
  - 금액, 주유량, 주행거리: 0 이상의 숫자
  - 새 주행거리가 그 차량의 이전 최대 주행거리보다 작으면 저장 전에 경고한다(저장은 막지 않는다).
  - 교체 주기: km와 개월 중 하나 이상
  - 연식: 1950 ~ 올해+1
- 권한은 RLS에서 막는다. 화면 숨김에 기대지 않는다.

## 8. 수락 기준

- AC-1: 캘린더 화면에서 '차계부' 탭을 누르면 주소가 `/car`가 되고 차계부가 보인다. '캘린더' 탭을 누르면 `/`로 돌아간다. 뒤로가기도 같다.
- AC-2: 기존 캘린더 테스트가 모두 통과하고, 캘린더 화면 요소의 배치가 바뀌지 않는다.
- AC-3: 로그인하지 않으면 차계부에 로그인 안내가 보이고 데이터 요청을 보내지 않는다.
- AC-4: 차량을 여러 대 등록하고 골라서 볼 수 있다. 다른 사용자 계정으로는 그 차량이 보이지 않는다(RLS).
- AC-5: 주유, 정비, 세차, 보험, 세금, 주차, 기타 기록을 추가, 수정, 삭제할 수 있다.
- AC-6: 가득 주유 기록이 2개 이상이면 연비가 5장의 규칙대로 계산된다.
- AC-7: 처음 등록한 차량에 4.1의 추천 교체 항목이 채워지고, 사용자가 주기를 바꾸면 다음 교체일이 다시 계산된다.
- AC-8: 교체 항목과 만기일을 저장하면 '차계부' 카테고리의 종일 일정이 캘린더에 생기고, 수정하면 날짜가 바뀌고, 삭제하면 일정도 사라진다.
- AC-9: 캘린더에서 연결된 일정을 지운 뒤 차계부를 열면 일정이 다시 생긴다.
- AC-10: 다음 교체일이 30일 이내이거나 남은 거리가 1,000km 이하이면 '곧 교체', 지났으면 '교체 시기 지남'이 보인다.
- AC-11: 통계 탭에 선택한 차량의 월별·종류별 지출 합계가 기록 금액의 합과 같게 나온다.
