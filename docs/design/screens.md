# 화면 구성 — 차계부

- 날짜: 2026-11-05 · 소유자: UX Designer · 상태: 초안(Product Owner 설계 검토 대기)
- 근거: [03_spec.md](../03_spec.md), [01_prd.md](../01_prd.md), [research/tech.md](../research/tech.md) T-4, 기존 코드의 `App.module.css`(FAB, 899px 경계)
- 짝 문서: [flows.md](flows.md)(흐름, 가정 UA-1~6)
- 이 문서는 구성·우선순위·상태·키보드 순서·폭별 차이만 정한다. 색, 글꼴, 간격 값, 아이콘은 UI Designer가 정한다. 코드는 쓰지 않는다.
- 설계 시작 폭은 320px이고 768, 1024, 1280px에서 달라지는 점을 5장에 적었다. 기존 캘린더의 모바일 경계(899px 이하, 또는 높이 500px 이하 터치 가로 화면)를 그대로 "모바일"로 부른다.

## 1. 정보 구조

```
앱
├─ 파일철 탭(전역, 2개)  ← 주 내비게이션
│    ├─ 캘린더  (/)       SCR-00  기존 화면, 변경 없음
│    └─ 차계부  (/car)    로그인 여부로 갈림
│         ├─ SCR-01  로그인 안내 (+ SCR-01a 세션 확인 중)
│         ├─ SCR-03  차량 0대 빈 상태
│         └─ SCR-02  차계부 본 화면 = 차량 영역 + 하위 탭 4개  ← 보조 내비게이션
│              ├─ SCR-02a 기록
│              ├─ SCR-02b 교체 알림
│              ├─ SCR-02c 만기일
│              └─ SCR-02d 통계
└─ 대화상자(화면 위에 열림)
     DLG-01 차량 양식 · DLG-02 삭제 확인 · DLG-03 기록 양식 · DLG-04 주행거리 감소 확인
     DLG-05 교체 완료 · DLG-06 교체 항목 양식 · DLG-07 만기일 양식 · 토스트(기존 장치)
```

- 내비게이션 개수: 파일철 탭 2개 + 하위 탭 4개 = 6개. 5~7개 이내다. 두 단계로 나뉘어 한 곳에 6개가 늘어서지 않는다.
- 하위 탭은 주소를 바꾸지 않는다(`/car` 유지, 명세 1.5). 새로고침하면 기록 탭, 가장 먼저 만든 차량으로 돌아온다.
- PRD에 없는 화면은 없다. 화면 ↔ 기능 대응은 아래 표다.

| 화면 | 기능 | 비고 |
|---|---|---|
| COMP-01 파일철 탭 | F-01, F-13, F-14 | 전역 부품. 위젯 모드에서는 그리지 않는다 |
| SCR-01 / 01a | F-02 | |
| SCR-03 | F-03(빈 상태) | |
| SCR-02 차량 영역 | F-03 | |
| SCR-02a | F-04, F-05 | |
| SCR-02b | F-06, F-12, F-08(MSG-11) | |
| SCR-02c | F-07, F-15, F-08(MSG-11) | |

| DLG-01~07, 토스트 | F-03, F-04, F-06, F-07, F-10, F-11, F-15 | |

## 2. 제목 계층과 공통 규칙

| 층 | `/car`의 내용 | 비고 |
|---|---|---|
| H1 | "차계부" (화면낭독기 전용, 문서에 하나) | 기존 H1 "캘린더 앱"과 같은 방식. 화면 전환 때 H1도 바뀐다 |
| H2 | "차량 정보", 활성 하위 탭 패널의 제목(기록·교체 알림·만기일·통계). 대화상자마다 자기 제목 | 화면에 보이지 않아도 된다(sr-only). 하위 탭 글자가 이미 제목 역할을 하기 때문 |
| H3 | 패널 안 구획(아래 각 화면) | 보이는 소제목 |

- 한 화면에 H1은 하나다. 단계를 건너뛰지 않는다(H1 > H2 > H3).
- 공통 키보드 규칙
  - 건너뛰기 링크(기존) → 본문(`main`) → … → 화면 전환 `nav`(DOM 순서는 본문 뒤, BR-02).
  - 화면 전환(탭 클릭, 로그인 복귀) 직후 포커스는 새 화면의 `main`으로 간다.
  - 모든 버튼·링크는 포커스 표시가 보이고, 포커스가 화면 밖으로 사라지지 않는다.
- 공통 대화상자 규칙(DLG-01~07)
  - 열면 포커스가 대화상자 안 첫 입력으로 간다. 삭제 확인(DLG-02)과 주행거리 감소 확인(DLG-04)은 "취소"로 간다.
  - Tab은 대화상자 안에서만 돈다. 뒷배경은 조작할 수 없다.
  - 저장 검사에 실패하면 포커스가 첫 오류 칸으로 가고, 오류 문구는 그 칸과 연결되어 읽힌다. 색만으로 구분하지 않는다.
  - 닫으면 포커스는 대화상자를 연 버튼으로 돌아간다. 열린 버튼이 사라졌으면(삭제 뒤) 같은 목록의 다음 항목, 없으면 패널 제목 영역(UA-3).
  - Esc는 닫는다. 입력 양식(DLG-01, 03, 05, 06, 07)은 창 바깥 클릭으로 닫히지 않는다(입력값을 실수로 잃지 않게, UA-7). 확인창(DLG-02, 04)은 바깥 클릭도 취소다(F-11).
- 상태 4종 용어
  - 로딩: 목록 자리에 뼈대(자리 표시) 행 3개와 "불러오는 중"(화면낭독기용). 영역이 `aria-busy`.
  - 빈: 안내 문구 하나 + 다음 행동 버튼 하나.
  - 오류: 화면 안 MSG-04 + "다시 시도" 버튼(토스트가 아니다).
  - 성공: 데이터가 보이는 평상시 상태. 저장 성공은 양식을 닫고 목록에 반영하는 것으로 끝낸다(별도 성공 토스트 없음, UA-2).

## 3. 화면별 정의

### COMP-01 파일철 탭 (F-01, F-13, F-14)

- 구성: "캘린더" 탭, "차계부" 탭. 링크(`href="/"`, `href="/car"`). `nav` "화면 전환" 안에 있다.
- 우선순위: 1 현재 탭(모양으로 구분, `aria-current="page"`), 2 다른 탭.
- 상태
  - 평상시: 두 탭 모두 보인다(로그인 여부와 무관).
  - 현재 탭: 앞으로 튀어나온 모양(색만으로 구분하지 않음). reduced-motion이면 전환 효과 없이 즉시.
  - 숨김: 위젯 모드(`?widget=1` 또는 위젯 저장값)에서는 DOM에 없다.
  - 가림: 새 일정 편집창 등 오버레이가 열리면 오버레이 뒤에 가려진다(층 60, 오버레이 100 아래).
- 키보드: Tab으로 두 링크에 도달, Enter로 이동. Ctrl·Cmd·Shift 클릭과 가운데 클릭은 가로채지 않는다.
- 배치는 4장.

### SCR-00 캘린더 (기존)

- 변경 없음. 요소 배치·크기·위치 불변(AC-01-5). 추가되는 것은 COMP-01 하나뿐이고, 기존 레이아웃 위에 겹쳐 놓는다.

### SCR-01a 세션 확인 중

- 구성: 로딩 표시 하나(스피너 또는 뼈대). 안내 문구를 깜빡이지 않는다.
- 상태: 최대 5초. 5초가 지나면 SCR-01로 바뀐다. 이 사이 데이터 요청은 0건이다.
- 키보드: 포커스 이동 대상 없음(`main`만). `aria-busy`.

### SCR-01 로그인 안내 (F-02)

- 구성과 우선순위: 1 MSG-02 "로그인하면 사용할 수 있습니다", 2 "로그인" 버튼(기본 강조).
- 상태: 평상시만 있다. 로그인 취소·실패는 같은 화면에 머문다(오류 문구를 새로 만들지 않는다. 기존 로그인 오류 처리 그대로).
- 키보드: 건너뛰기 → `main` → 로그인 버튼 → 화면 전환 nav. 로그인 버튼이 이 화면의 첫 포커스 대상이다.
- 폭: 모든 폭에서 문구와 버튼이 가운데 정렬된 한 열이다. 폭이 넓어도 더 늘어나지 않는다.

### SCR-03 차량 0대 빈 상태 (F-03)

- 구성: 1 문구 "차량을 추가해 주세요", 2 "차량 추가" 버튼. 하위 탭과 차량 카드는 없다(명세 1.5).
- 상태: 목록 불러오는 동안 로딩, 실패하면 MSG-04 + 다시 시도.
- 키보드: `main` → 차량 추가 버튼.

### SCR-02 차계부 본 화면: 차량 영역

- 구성과 우선순위
  1. 차량 선택 상자(여러 대). 차량이 1대여도 보인다(어떤 차인지 알린다).
  2. "차량 추가" 버튼.
  3. 차량 정보 카드(H2 "차량 정보"). 별칭, 차종, 연식, 번호판, 현재 주행거리. 빈 값은 칸을 숨기지 않고 "-"로 둔다. `[가정]` 칸이 사라지면 사용자가 입력하러 갈 단서가 없다. 번호판은 화면에만 보이고 캘린더에는 가지 않는다(AC-08-10).
  4. 카드의 "수정", "삭제" 버튼.
  5. 하위 탭 4개와 패널.
- 상태
  - 로딩: 선택 상자 자리에 뼈대, 카드 뼈대, 하위 탭은 보이되 패널은 뼈대.
  - 오류: 차량 목록을 못 읽으면 영역 전체가 MSG-04 + 다시 시도 하나만 보인다(하위 탭 숨김).
  - 성공: 위 구성 그대로.
- 키보드 순서(위→아래, 왼→오른): 차량 선택 상자 → 차량 추가 → 수정 → 삭제 → 하위 탭 목록 → 패널 내용 → (화면 전환 nav).
- 하위 탭 키보드(탭 목록 패턴)
  - 탭 목록 전체가 Tab 정지점 하나다. 활성 탭 하나만 Tab으로 들어간다.
  - 좌우 화살표가 이전·다음 탭으로 옮기고 즉시 그 패널을 연다. Home·End는 첫·마지막 탭.
  - 탭 글자는 "기록", "교체 알림", "만기일", "통계". 선택 탭은 색만이 아니라 밑줄 또는 굵기로도 구분한다.
- 하위 탭은 차량을 바꿔도 유지된다(UA-1). 새로고침하면 "기록"이다.

### SCR-02a 기록 탭 (F-04, F-05)

- 구성과 우선순위
  1. 연비 요약(H3 "연비"): "연비 12.3km/L" 또는 "연비: 가득 주유 기록이 2건 이상 필요합니다". 가장 먼저 눈에 들어와야 한다.
  2. "기록 추가" 버튼(기본 강조).
  3. 기록 목록(H3 "기록"). 행 = 날짜 · 종류 이름 · 금액(천 단위 쉼표 + "원") · (있으면) 주행거리 · 메모 한 줄. 주유 행은 주유량(L)을, 구간 끝 가득 주유 행은 그 구간 연비를 덧붙인다.
- 정렬: 날짜 내림차순, 같은 날짜는 나중에 만든 것이 위(BR-09).
- 상태
  - 로딩: 연비 자리와 목록 뼈대.
  - 빈: "기록이 없습니다" + 기록 추가 버튼 하나(연비 요약은 안내 문구 그대로 보인다). 같은 이름의 버튼이 둘 보이지 않게 상단 "기록 추가"는 숨기고 빈 상태의 버튼을 기본 강조로 쓴다(UA-11).
  - 오류: MSG-04 + 다시 시도.
  - 성공: 위 구성. 저장·수정·삭제 뒤에는 새로고침 없이 갱신(NFR-03).
- 행 동작: 행 전체가 버튼이다(누르면 DLG-03 수정 양식). 삭제는 수정 양식 안에만 둔다(행마다 삭제 버튼을 두면 오조작이 늘고 좁은 폭에서 터치 목표가 겹친다). `[가정]`
- 키보드: 연비 요약(읽기 전용) → 기록 추가 → 기록 행들(위→아래, Enter로 수정).

### SCR-02b 교체 알림 탭 (F-06, F-12, F-08)

- 구성과 우선순위
  1. MSG-12 "참고용 값입니다. 차량 매뉴얼을 우선하세요". 목록 위에 항상 보이고 닫을 수 없다. 읽을 수 있는 텍스트다.
  2. "항목 추가" 버튼.
  3. 항목 목록(H3 "교체 항목"). 행 = 이름 · 주기(`10,000km / 12개월`) · 마지막 교체(날짜, 주행거리) · 다음 교체일 또는 MSG-18 · 남은 거리 · 상태 배지 · "교체 완료" 버튼 · (일정 쓰기 실패일 때만) MSG-11 버튼.
  4. 배지: "교체 시기 지남", "곧 교체". 정상은 배지 없음. 글자로 표시하고 색은 보조다.
- 정렬 `[가정, UA-8]`: 지남 → 곧 교체 → 정상 순, 같은 상태는 다음 교체일 빠른 순, 날짜가 없는 항목은 맨 뒤. 이유는 사용자가 위에서부터 급한 것만 보면 되게 하려는 것이다. 명세에 정렬 규칙이 없으므로 PO 확인을 요청한다.
- 상태
  - 로딩: 뼈대. 오류: MSG-04 + 다시 시도. 빈: "교체 항목이 없습니다" + 항목 추가 버튼 하나(MSG-12는 그대로). 상단 "항목 추가"는 숨기고 빈 상태의 버튼을 기본 강조로 쓴다(UA-11).
  - 행 단위: 다음 교체일 칸이 MSG-18 "주행거리 기록 부족"일 수 있고 이때 일정은 없다. 오류가 아니라 정상 표시다.
  - MSG-11 버튼: 진행 중 비활성, 성공하면 사라진다.
- 행 동작: 이름 영역을 누르면 DLG-06(수정). "교체 완료"는 행 안의 별도 버튼(DLG-05). 삭제는 DLG-06 안에 있다(SCR-02a와 같은 이유).
- 키보드: MSG-12(읽기 전용) → 항목 추가 → 각 행의 이름 버튼 → 교체 완료 → (있으면) MSG-11 버튼 → 다음 행.

### SCR-02c 만기일 탭 (F-07, F-15, F-08)

- 구성: 고정 순서 3행 — 보험 만기, 자동차세 납부, 정기검사(H3 없이 행 목록. 행 제목이 구분 역할).
- 행 = 종류 이름 · 날짜 또는 "날짜 없음" · 버튼. 값 없음 → "입력" 하나. 값 있음 → "수정", "삭제". 값이 있는데 입력 버튼은 없다(AC-07-6). MSG-11 버튼은 일정 쓰기 실패일 때만 행에 붙는다.
- 상태: 로딩 뼈대(3행), 오류 MSG-04 + 다시 시도. 빈 상태는 따로 없다(3행이 모두 "날짜 없음"이면 그것이 빈 상태다). 임박·지남 배지는 없다(F-07).
- 키보드: 행 순서대로 각 행의 버튼(입력 또는 수정 → 삭제 → MSG-11).

### SCR-02d 통계 탭 (F-09, F-05)

- 구성과 우선순위
  1. 월 선택(H3 "월 선택"): 이전 달 · 현재 선택 달(`2026-11`) · 다음 달.
  2. 선택한 달 총합(큰 숫자)과 종류별 합계(H3 "종류별 합계", 기록 있는 종류만, 금액 큰 순).
  3. 월별 합계 목록(H3 "월별 합계"): 오늘이 속한 달부터 12개월, 최근 달이 위, 기록 없는 달은 0원. 선택한 달과 무관하다.
  4. 연비 변화 목록(H3 "연비 변화"): `날짜 — 12.3km/L`, 날짜 오름차순. 구간이 없으면 "가득 주유 기록이 2건 이상 필요합니다".

## 4. 파일철 탭 배치 (F-14 / R-14 조건 1~4)

### 4.1 결정

| 구분 | 위치 | 터치 영역(각 탭) | 묶음 |
|---|---|---|---|
| 모바일(≤899px, 또는 높이 500px 이하 터치 가로 화면) | 화면 오른쪽 끝에 붙임(`right: 안전영역`), 세로로 쌓음 | 너비 28px × 높이 56px | 두 탭 합쳐 28×112px. 묶음의 세로 중심은 뷰포트 높이의 40% 지점 |
| 데스크톱(≥900px) | 화면 오른쪽 끝에 붙임, 세로로 쌓음 | 너비 32px × 높이 96px | 합쳐 32×192px. 세로 중심은 뷰포트 높이의 50% |

- 탭 글자는 가로로 쓰고 회전하여 세로로 읽게 한다(세로쓰기 속성 대신, tech.md T-4). 글자 크기는 UI Designer가 정하되 탭 안에 들어가야 한다.
- 터치 영역은 눈에 보이는 탭 모양과 같다. 눈에 안 보이는 터치 확장 영역을 만들지 않는다(조건 2).
- `position: fixed`로 레이아웃 흐름 밖에 둔다. 캘린더 쪽에 여백·너비·높이를 더하지 않는다(조건 3).
- 층은 FAB(50)보다 위, 오버레이(100)보다 아래(예 60).
- `/car` 화면 자신은 탭 폭 + 8px만큼 오른쪽에 여백을 둬서 탭이 내용 위에 올라타지 않는다. 이것은 `/car` 화면의 레이아웃이므로 캘린더 불변(AC-2)과 무관하다.

### 4.2 조건별 확인

기존 FAB은 `right: 20px; bottom: 20px + 안전영역; 52×52px`이므로 FAB의 화면 점유 구역은 가로 오른쪽에서 20~72px, 세로 아래에서 20~72px(+안전영역)이다.

| 조건 | 설계 | 판정 |
|---|---|---|
| 1 FAB 터치 영역과 겹치지 않음 | 두 영역은 세로로 떨어진다. 탭 묶음 아래 끝 = 0.4H + 56px, FAB 위 끝 = H − 72px − 안전영역. 0.4H + 56 < H − 72 는 H > 213px이면 성립한다 | 만족 |
| 2 탭 밖에서 시작한 가로 스와이프는 그대로 | 탭은 28×112px의 눈에 보이는 영역만 받는다. 스와이프 영역(`SwipeableViewport`) 바깥에 있는 형제 요소라서 그 영역의 이벤트를 가로채지 않는다. 확장 터치 영역 없음 | 만족 |
| 3 겹칠 수는 있으나 캘린더 크기·위치 불변 | fixed 배치, 캘린더 쪽 여백·크기 변화 없음 | 만족 |
| 4 터치 영역 ≥ 24×44px | 28×56px | 만족 |

계산 예(탭 묶음의 위·아래 끝 / FAB 위 끝, 안전영역 0 가정)

| 화면 | H | 탭 묶음 세로 구간 | FAB 세로 구간 | 겹침 |
|---|---|---|---|---|
| 360×640 | 640 | 200 ~ 312px | 568 ~ 620px | 없음 |
| 320×568 | 568 | 171 ~ 283px | 496 ~ 548px | 없음 |
| 640×360(가로 모드, 터치) | 360 | 88 ~ 200px | 288 ~ 340px | 없음 |

네 조건은 동시에 만족되므로 Product Owner에게 조건 충돌을 알릴 일은 없다(BR-31).

### 4.3 알려진 대가(PO가 알아야 할 것)

- 모바일에서 탭 묶음(28×112px)이 월 그리드 오른쪽 끝(토요일 칸)을 일부 가린다. 360px 폭에서 칸 폭이 약 51px이므로 그 구간의 토요일 칸은 왼쪽 약 23px만 눌러진다. 조건 3이 허용하는 겹침이다. 가려지는 칸 수는 탭이 걸치는 주 1~2행이다. 시작 위치를 아래쪽으로 옮길 수는 있으나 FAB과 가까워져 조건 1의 여유가 줄어든다.
- 탭 위에서 시작한 터치는 탭 누르기로만 처리되고 스와이프로 처리되지 않는다(조건 2는 탭 밖에서 시작한 스와이프만 요구한다).
- 새 일정 편집창 등이 열리면 탭은 가려진다. 편집창을 닫기 전에는 화면 전환을 할 수 없다.

### 4.4 실기기 위험과 대안(UA-6)

- 안드로이드 제스처 내비게이션의 "오른쪽 가장자리에서 밀면 뒤로 가기"가 탭과 겹칠 수 있다. 실기기는 미확인이다(tech.md T-4).
- 확인 방법: Android Chrome과 iOS Safari 실기기에서 탭 위를 누르고 밀어 뒤로 가기가 걸리는지 본다.
- 걸리면 대안: 모바일에서만 탭 묶음을 오른쪽 끝에서 12px 안쪽으로 띄운다(떠 있는 알약 모양, 파일철 느낌은 줄어듦). 세로 위치·크기는 그대로라 조건 1~4는 유지된다. 이 경우 UI Designer와 모양을 조정한다.
