# 화면 구성 v0.2 — 차계부 (F-17~F-28)

- 날짜: 2026-11-21 · 소유자: UX Designer · 상태: 초안(UI Designer 검토 대기)
- 근거: [03_spec.md](../03_spec.md) F-17~F-28·MSG-22~32, [flows-v0.2.md](flows-v0.2.md)(흐름, 가정 UA-12~22), v0.1 [screens.md](screens.md)
- 이 문서는 v0.1 화면에서 바뀌거나 새로 생기는 것만 다룬다. 바뀌지 않은 화면과 공통 규칙(제목 계층, 대화상자 포커스 규칙, 상태 4종 용어)은 screens.md 2장을 그대로 쓴다. 시각 값(색, 글꼴, 치수)은 UI Designer가 정한다.
- 캘린더 화면(SCR-00)은 바꾸지 않는다(BR-37). 파일철 탭 배치(4장)도 바뀌지 않는다.
- 설계 시작 폭은 320px이고 768, 1024, 1280px에서 달라지는 점은 5장이다.

```

├─ COMP-02 계정 영역 (항상 맨 위)
```

- PRD v0.2에 없는 화면은 없다. 설정 창은 계정 메뉴에서만 열린다. 설정으로 가는 별도 하위 탭이나 주소는 없다(주소는 `/car` 그대로).

## 3. 화면별 정의

### COMP-02 계정 영역과 계정 메뉴 (F-17, F-18)

- 위치: 차계부 맨 위 한 줄, 차량 영역보다 위(UA-12). 로그인한 `/car`의 모든 상태(로딩, 오류, 차량 0대, 정상)에서 보인다. 로그인 안내 화면에는 없다.
- 구성과 우선순위
  1. 계정 버튼 하나. 안에 ① 사진 자리(원형, 사진 또는 이름 첫 글자), ② 이름 한 줄, ③ 이메일 한 줄, ④ 펼침 표시(아래 화살표).
  2. 계정 메뉴(버튼을 누르면 버튼 바로 아래에 열림). 항목 2개, 순서는 "설정", "로그아웃".
- 상태
  - 평상시: 사진 또는 이니셜, 이름, 이메일. 이름이 없으면 이름 줄 없이 이메일만 보이고 이니셜은 이메일 첫 글자(AC-17-4).
  - 사진 불러오는 중·실패·주소 없음·`https:` 아님: 이니셜 원형. 사진 자리는 항상 같은 크기라서 사진이 늦게 떠도 다른 요소가 움직이지 않는다. 깨진 이미지 아이콘은 보이지 않는다.
  - 긴 이름·이메일: 각각 한 줄 말줄임. 가로 스크롤이 생기지 않는다.
  - 메뉴 열림/닫힘: 열린 동안 버튼은 "펼침" 상태를 화면낭독기에 알린다. 항목 높이는 44px 이상.
  - 이 영역에는 로딩·빈·오류 상태가 없다(로그인 정보에서 바로 읽는다). 차량 목록이 실패해도 그대로 보인다(AC-17-8).
- 접근성 이름: 계정 버튼은 "계정 메뉴, 김차계"(이름이 없으면 "계정 메뉴, carbook@example.com")로 읽힌다. 사진은 읽지 않는다(AC-17-10). 이름·이메일은 일반 글자로만 그린다.
- 키보드
  - Tab으로 계정 버튼에 닿는다. 건너뛰기 링크 → `main` 다음이 계정 버튼이다.
  - Enter 또는 Space 또는 아래 화살표로 메뉴를 열고 첫 항목("설정")에 포커스가 간다.
  - 위·아래 화살표는 항목 이동(끝에서 순환 없음), Home·End는 처음·끝 항목, Enter는 선택.
  - Esc 또는 메뉴 밖 클릭 또는 Tab으로 메뉴가 닫히고, Esc·클릭이면 포커스가 계정 버튼으로 돌아온다(AC-18-1).
- 항목 동작
  - "설정" → 메뉴 닫힘 → DLG-09 열림.
  - "로그아웃" → 메뉴 닫힘 → DLG-08 열림. 이 시점 로그아웃 요청은 0건(AC-18-2).
- 구현 메모: 이 영역은 차량 목록 불러오기 상태와 무관하게 그려야 한다. 현재 v0.1은 불러오기 실패 때 화면 전체를 오류 문구로 바꾸므로 계정 영역을 그 바깥(위)에 둬야 AC-17-8이 맞는다.

### DLG-08 로그아웃 확인창 (F-18)

- 기본은 확인창 공통(DLG-02와 같은 규칙). 제목 "로그아웃", 본문 MSG-22 "로그아웃할까요? 모든 기기에서 로그아웃됩니다", 버튼 "로그아웃"(확정), "취소".
- 열면 포커스가 "취소"에 있다(AC-18-2). 취소·Esc·창 밖 클릭은 취소이고 포커스가 계정 버튼으로 돌아온다(AC-18-5).
- 상태
  - 진행 중: "로그아웃" 버튼 비활성(중복 요청 방지). 닫기 동작은 막지 않는다.
  - 실패: 창이 닫히고 MSG-23 토스트, 포커스는 계정 버튼(AC-18-6).
  - 성공: 창이 닫히고 SCR-01(MSG-02 + 로그인 버튼)이 보이며 계정 영역이 사라진다. 포커스는 `main`(화면 전환 규칙).
  - 인증이 이미 만료돼 있어 로그아웃 요청이 인증 오류로 실패하는 경우는 명세에 없다. MSG-23으로 처리한다.

### DLG-09 설정 창 (F-19, F-20)

- 제목(H2) "설정". 구역 둘은 H3. 맨 아래에 "닫기" 버튼 하나(저장 버튼 없음, UA-18). Esc·창 밖 클릭으로도 닫히고 포커스는 계정 버튼으로 돌아온다(AC-19-11). 창 밖 클릭은 입력 양식이 아니므로 닫힌다(저장할 입력이 없다).
- 구역 1 "기본 차량"(H3)
  - 구성: 라디오 목록. 첫 항목 "지정 안 함", 다음부터 차량 별칭(보조로 차종). 현재 지정이 선택돼 있다.
  - 안내 한 줄(UA-18): "지금 보는 차량은 그대로이고 다음에 차계부를 열 때부터 적용됩니다"(UA-18, PO 확정 2026-11-24).
  - 동작: 고르는 즉시 저장한다. 저장 중에는 그 구역의 라디오가 비활성이고 화면낭독기에 "저장 중"이 읽힌다.
  - 실패: MSG-01 토스트, 선택이 이전 값으로 돌아간다(AC-19-7). 인증 만료: NTC-01(MSG-30) 안내, 선택은 이전 값(AC-27-10 다).
  - 읽기 실패(UA-13): 선택 표시 없이 "현재 지정을 불러오지 못했습니다"를 보이고 고를 수는 있다.
  - 차량 0대: 라디오 없이 "차량을 추가해 주세요"만 보인다(AC-19-10).
- 구역 2 "추천 교체 주기 되돌리기"(H3)
  - 구성: ① 대상 차량 한 줄(`대상 차량: {별칭}`, UA-19), ② 설명 한 줄(마지막 교체일·주행거리와 직접 추가한 항목은 그대로 두고 주기만 추천 값으로 되돌림), ③ "되돌리기" 버튼, ④ 결과 상태 문구 자리.
  - 상태
    - 평상시: 버튼 활성.
    - 차량 0대: 버튼을 누를 수 없고(aria-disabled) 이유로 "차량을 추가해 주세요"를 보인다(AC-20-10).
    - 되돌릴 것 없음: 누르면 확인창 없이 ④에 MSG-24 "추천 주기와 다른 항목이 없습니다"를 보이고 쓰기는 하지 않는다(AC-20-4, UA-21). 화면낭독기가 읽는다(상태 알림).
    - 완료: ④에 "N개 항목의 주기를 되돌렸습니다"(UA-14, PO 확정 2026-11-24. 토스트는 없고 설정 창 안의 한 줄). 일정 쓰기 실패가 있으면 이어서 "일부 항목은 캘린더에 반영하지 못했습니다. 교체 알림 탭에서 다시 시도하세요".
- 로딩: 설정 창은 이미 불러온 차량·항목·기본 차량 값으로 즉시 열린다. 별도 로딩 화면이 없다.
- 키보드 순서: 창 제목 → 기본 차량 라디오(하나의 정지점, 화살표로 이동) → 안내 → 되돌리기 → 닫기. 열면 포커스는 선택된 라디오(차량 0대면 "닫기").
- 안내 NTC-01은 이 창 안 구역 위쪽에 놓인다(아래 NTC-01).

### DLG-10 추천 주기 되돌리기 미리보기 (F-20)

- 설정 창 위에 겹쳐 열리는 확인창. 제목 "추천 교체 주기 되돌리기", 대상 차량 별칭 한 줄, 본문 MSG-25(`{N}`은 바뀌는 항목 수), 항목 목록, 버튼 "되돌리기"(확정), "취소".
- 목록: 한 줄이 한 항목이다. 첫 줄 항목 이름, 둘째 줄 `지금 주기 → 추천 주기`(예 `15,000km / 6개월 → 10,000km / 12개월`). 좁은 폭에서는 둘째 줄이 두 줄이 될 수 있고 이때 `→ 추천 주기`가 아래 줄 맨 앞에 온다(R4). 추천 7개의 순서이고 바뀌는 항목만 있다. 화면낭독기는 "엔진오일, 지금 15,000km / 6개월, 추천 10,000km / 12개월"로 읽는다. 최대 7개라 목록 영역이 길어지면 창 안에서만 스크롤하고 버튼 줄은 항상 보인다.
- 열면 포커스는 "취소"다(되돌릴 수 없는 일괄 변경이라서). 취소·Esc·창 밖 클릭은 취소이고 쓰기 요청은 0건이다(AC-20-5). 닫히면 포커스는 설정 창의 "되돌리기" 버튼으로 돌아간다.
- 상태
  - 진행 중: "되돌리기" 버튼 비활성(연속 누름은 1회, AC-20-9).
  - 성공: 창이 닫히고 포커스는 설정 창의 "되돌리기" 버튼(UA-14의 결과 문구가 그 구역에 뜬다).
  - 실패: MSG-01 토스트, 창은 열린 채 버튼이 다시 활성(UA-17). 항목은 하나도 바뀌지 않는다.
  - 인증 만료: NTC-01을 이 창의 버튼 줄 위에 보이고 "되돌리기"는 비활성, "취소"는 남는다.

### NTC-01 로그인 만료 안내 (F-27)

- 구성: 아이콘 + MSG-30 "로그인이 만료됐습니다. 다시 로그인해 주세요" + "로그인" 버튼. 보조 문구(UA-16): "다시 로그인하면 입력한 내용은 사라집니다".
- 위치와 동작(UA-15): 쓰기를 시도한 대화상자의 고정 영역(버튼 줄 바로 위, 본문이 스크롤돼도 밀려나지 않는 부분, R1). 대화상자를 닫으면 사라진다. 나타나는 순간 화면낭독기가 알림으로 읽고(NFR-21) 포커스는 옮기지 않는다(입력 중이던 칸을 지키려는 것). 안내가 보이는 동안 그 대화상자의 저장·확정 버튼은 비활성이고 입력값은 그대로 남는다.
- 적용 대상: 기록·차량·교체 항목·만기일 양식, 교체 완료, 삭제 확인창, DLG-09의 기본 차량, DLG-10(AC-27-4, 6, 10).
- "로그인" 버튼: 현재 주소(`/car`)로 돌아오는 Google 로그인을 시작한다.
- MSG-29(로그인 안내 화면의 실패 문구)는 NTC-01과 다른 자리다. 아래 SCR-01.

### SCR-01 로그인 안내 (변경, F-27)

- 구성: 1 (조건부) MSG-29 "로그인하지 못했습니다. 다시 시도해 주세요", 2 MSG-02, 3 "로그인" 버튼. MSG-29는 MSG-02와 버튼 사이에 놓이고 오류 표시(아이콘 + 글자, 색만으로 구분하지 않음)를 쓴다. 나타나는 순간 알림으로 읽힌다(AC-27-9).
- 상태: 처음 열기와 로그아웃 직후에는 MSG-29가 없다. 로그인 실패·취소로 돌아오면 있다. 버튼을 다시 누르면 사라지고 로그인을 새로 시작한다(AC-27-3). 성공하면 없다.
- 키보드: 변경 없음(`main` → 로그인 버튼). 실패로 돌아온 경우 포커스는 `main`이고 알림이 읽힌다.

### SCR-02b 교체 알림 탭 (변경, F-24, F-26, F-21)

- 미입력 항목(마지막 교체일 없음, 새 차량의 추천 항목)
  - 마지막 교체 자리에 "미입력"(보조 색, 글자로 구분). 다음 교체일 자리에 MSG-26 "마지막 교체일을 입력하세요". 남은 거리 칸과 상태 배지는 없다. "교체 완료" 버튼은 있다.
  - 목록 맨 뒤에 놓인다(UA-8). 미입력이 아닌 항목이 있으면 그 항목들이 위에 있다.
  - 행의 접근성 이름: `엔진오일, 마지막 교체일 미입력, 수정`.
  - 표형(≥1024px)에서 MSG-26은 다음 교체일 열에 두 줄로 줄바꿈될 수 있고 말줄임으로 자르지 않는다.
  - 확정(UA-20, PO 확정 2026-11-24, 행별 표시에 더함): 미입력 항목이 하나 이상이면 목록 위에 "마지막 교체일을 입력하면 다음 교체일을 계산합니다" 한 줄. 7개에 같은 MSG-26이 반복되는 부담을 줄인다.
- 추정 표시(UA-20, PO 확정 2026-11-24): 다음 교체일이 km 기준이면 날짜 옆에 "추정"을 보인다(BR-55 판정과 같다). 화면 글자는 "추정"이고 화면낭독기에는 "주행거리 기준 추정"으로 읽힌다(R2). 캘린더 일정 메모(MSG-28)와 뜻을 맞추려는 것이다.
- MSG-11 재시도 버튼 배치(F-21)
  - ≤1023px: v0.1과 같다.
  - ≥1024px(UA-22): 버튼을 그 항목 행 아래 한 줄로 내려 행 전체 폭을 쓴다. 문구 "캘린더 반영 실패, 다시 시도" 전체가 한 줄에 보이고 어느 덩어리도 끊기지 않는다. 대안(줄을 내리지 않는 경우)은 동작 열 폭을 문구 첫 덩어리가 들어갈 만큼 확보하고 띄어쓰기 자리에서만 줄바꿈하는 것이다(`word-break` 규칙은 UI Designer).
  - 버튼이 이웃 열이나 행 밖으로 넘치지 않는다(AC-21-1, 2). 터치 영역은 44px 이상(AC-21-3).
- 로딩·빈·오류 상태는 v0.1과 같다.

### DLG-05 교체 완료 (변경, F-25)

- 입력 칸(날짜, 주행거리) 아래, 버튼 줄 위에 MSG-27 "비용은 기록 탭에서 정비로 추가하세요"를 한 줄 보인다. 안내 표시(정보 아이콘 + 글자), 닫기 버튼 없음. 대화상자의 설명(`aria-describedby`)에 연결해 열 때 화면낭독기가 함께 읽는다(AC-25-4).
- 미입력 항목의 교체 완료 대화상자에도 같다(AC-25-3). 날짜 기본값 오늘, 주행거리 기본값 현재 주행거리는 v0.1 그대로다.
- NTC-01이 뜨면 MSG-27 아래, 버튼 줄 위에 놓인다.

### DLG-06 교체 항목 양식 (변경, F-24)

- 미입력 항목을 열면 마지막 교체일·마지막 교체 주행거리 칸이 비어 있다. 오늘 날짜로 채우지 않는다. 비운 채 저장하면 MSG-05(마지막 교체일)가 칸 아래에 보이고 요청은 0건이다(AC-24-6). 새 항목 추가 양식의 기본값(오늘)은 v0.1 그대로다.

### SCR-02c 만기일 탭 (변경, F-22)

- 삭제 성공 직후 그 행은 "날짜 없음 + 입력 버튼"으로 바뀌고 "삭제" 버튼은 사라진다. 포커스는 성공한 그 순간 같은 행의 "입력" 버튼으로 옮긴다. 확인창이 닫히는 동안 포커스가 `body`에 있는 순간이 없어야 한다(AC-22-1).
- 삭제 실패·취소·Esc는 포커스가 그 행의 "삭제" 버튼으로 돌아온다(AC-22-2, 3). 표시·동작은 모든 폭에서 같다.

### 토스트 (추가분)

| 문구 | 언제 | 종류 | 읽힘 |
|---|---|---|---|
| MSG-31 캘린더에 `{YYYY-MM-DD}` 일정으로 추가했습니다 | 교체 항목·만기일 저장이 성공하고 일정을 쓰거나 바꿨을 때 | 성공 | 상태 알림 |
| MSG-32 저장했습니다 | 저장은 성공했으나 일정이 없거나 안 바뀌었거나 쓰기에 실패했을 때 | 성공(중립) | 상태 알림 |
| MSG-23 로그아웃하지 못했습니다. 다시 시도해 주세요 | 로그아웃 요청 실패 | 오류 | 알림 |

- 기존 토스트 장치와 위치를 그대로 쓴다. MSG-31은 날짜가 들어가 모바일 320px에서 두 줄이 된다. 두 줄일 때 알약 모서리가 어색해 보이는 점(UI 검토 R3)은 기존 `ToastViewport` 수정이 필요해 이번 범위에서 고치지 않는다. 글자는 띄어쓰기 자리에서만 끊는다(UI 규격 12.11). 어색함이 실사용에서 거슬리면 별도 개선 요청으로 다룬다.
- 기록 저장, 차량 저장, 삭제, 되돌리기에는 새 성공 토스트가 없다(VQ-12).

## 4. 키보드 이동 순서 (SCR-02 갱신)

건너뛰기 링크 → `main` → **계정 버튼**(열리면 메뉴 항목) → 차량 선택 상자 → 차량 추가 → 수정 → 삭제 → 하위 탭 목록 → 패널 내용 → 화면 전환 nav.

- 화면 전환 직후 포커스는 `main`이다. 계정 버튼이 `main` 안 첫 정지점이다.
- 대화상자(DLG-08, 09, 10)는 v0.1 공통 규칙대로 안에서만 Tab이 돈다(NFR-18). DLG-10은 DLG-09 위에 겹치므로 Esc는 맨 위 창 하나만 닫는다.

## 7. 이 설계의 열린 점 (PO 확인 요청)
