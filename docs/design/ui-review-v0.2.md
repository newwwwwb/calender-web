## 2. 규격 반영 (UX 문서 변경 없음, 규격에서 처리)

| 번호 | 항목 | 처리 |
|---|---|---|
| R5 | ≥1024px 표형 "다음 교체일" 열 112px에는 날짜 + "추정" 태그, MSG-26 두 줄이 들어가기에 좁다 | 열을 136px로 넓히고 동작 열은 나머지 108px(본문 최대 폭 880px에서 "교체 완료" 버튼이 들어감)로 한다. 앞 여섯 열 합계 772px(components 6.4, 12.9) |
| R6 | UA-22 보조 행: 표에서 MSG-11 버튼이 행 아래 한 줄이 되면 위 행과 떨어져 다른 행처럼 보일 수 있다 | 위 행의 아래 선을 지우고 보조 행 아래에만 선을 둔다. 버튼은 이름 열 시작에 맞춰 왼쪽 정렬(12.9) |
| R7 | MSG-11 글자 줄바꿈("띄어쓰기 자리에서만") | MSG-11 버튼에만 `word-break: keep-all; white-space: normal`(12.9). 다른 버튼은 한 줄 규칙 유지 |
| R8 | DLG-09 결과 문구(UA-14)·MSG-24가 설정 창 안에서 나타나면 화면낭독기가 읽어야 한다 | 상태 영역(`role="status"`)이 문구 없을 때도 DOM에 있고 높이 0이다(12.3). 문구가 거절돼도 영역을 지우면 된다 |
| R9 | DLG-10이 DLG-09 위에 겹침 | `--z-overlay-stacked`(110) 토큰을 추가하고 스크림을 한 번 더 깐다(DLG-09가 더 어두워진다)(12.7, tokens 3.2) |
| R10 | UA-16 보조 문구 "다시 로그인하면 입력한 내용은 사라집니다"가 버튼 "옆"이면 320px에서 못 들어간다 | <440px는 문구 아래 줄, 버튼 맨 아래. ≥440px에서만 버튼이 오른쪽(12.4). 문구가 거절되면 그 한 줄만 뺀다 |
| R11 | 계정 영역을 sticky로 고정할지 | 고정하지 않는다. 가로 화면(640×360)에서 56px를 계속 차지하면 본문이 모자란다(12.1) |

## 3. 확인 (문제 없음)

| 항목 | 확인 내용 |
|---|---|
| 계정 메뉴와 파일철 탭 겹침 | 메뉴 폭이 `--tab-gutter`(36/40px)를 뺀 본문 폭이라 탭(z 60)과 겹치지 않는다. 메뉴 층은 55 |
| 계정 영역 320px 폭 | 안쪽 폭 268px에서 아바타 40px + 여백을 빼면 글자 약 168px. `carbook@example.com`(12px, 약 115px)은 말줄임 없이 들어간다 |
| 사진 자리 크기 고정 | 아바타 40×40px 고정, 이니셜 위에 사진을 겹쳐 레이아웃이 움직이지 않는다(12.2) |
| 터치 영역 44px | 계정 버튼 56px, 메뉴 항목·라디오 줄·로그인·MSG-11 버튼 모두 44px 이상 |
| 오류·안내가 색만으로 구분되지 않음 | 모두 아이콘 모양 + 글자(12.3). 선택 라디오는 점 모양, "추정"은 글자 |
| DLG-09 "닫기" 하나 | 저장할 입력이 없어 secondary 버튼 하나로 충분하다. 확정 변경은 DLG-10이 맡는다 |
| 상태 점검표(screens-v0.2 6장) | COMP-02, DLG-08~10, SCR-01, SCR-02b 미입력의 로딩·빈·오류·성공이 규격에 모두 대응한다 |
