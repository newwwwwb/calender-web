# 차계부 v0.1 사용자 관점 검토

- 날짜: 2026-11-21 · 대상: 운영 차계부 `/car`(v0.1.0) · 요청: god(conv-carbook-ux-review)
- 구성: A장은 화면·흐름·사용성(UX Designer), B장은 유사 차계부 앱 대비 빠진 기능(Market Researcher), C장은 합친 우선순위 상위 5개.
- 기준: Nielsen의 10가지 사용성 휴리스틱(H1 시스템 상태 가시성, H2 현실과의 일치, H3 사용자 통제, H4 일관성, H5 오류 예방, H6 회상보다 인식, H7 유연성·효율, H8 미니멀 디자인, H9 오류 복구, H10 도움말)과 Krug의 "생각하게 만들지 마라".
- 심각도: P1 핵심 가치를 해치거나 데이터를 틀리게 만든다. P2 자주 마주치는 불편 또는 오해. P3 거슬리지만 우회할 수 있다.
- 이 문서는 구현·티켓을 만들지 않는다. v0.2 범위(계정 영역, 설정, P3 3건)와 겹치는 항목은 `[v0.2 겹침]`으로 표시만 했다.

## A. 화면·흐름·사용성 (UX Designer)

### A.0 검토 방법과 한계

- 로그인 화면 이후는 운영 화면을 직접 열지 않았다(계정 공유 금지). `src/carbook/` 구현 코드, `03_spec.md`, `docs/qa/report.md`, `docs/design/`를 읽고 사용자가 보게 될 화면과 흐름을 재구성했다. 아래 "근거"는 코드 위치이고, 화면에서 직접 본 것이 아니다.
- 따라서 화면 배치·글자 크기·실제 체감 속도는 이 검토에서 확인하지 못했다. 그런 항목은 "미확인"으로 적었다.
- 설계 시점의 가정(UA-n)이 이번 검토로 틀렸을 수 있는 것은 항목에 UA 번호를 적었다. 내가 정한 가정이라 스스로 다시 검토했다.

### A.2 이미 알려진 항목(재확인)

- P3 3건(1280px 재시도 버튼 줄바꿈, 만기일 탭 포커스 0.7초, AC-04-9 실환경 재측정)은 `docs/release/verdict.md`·`retro/v0.1.0.md`에 있고 v0.2 범위다. 이번 검토에서 새로 찾은 것이 아니다.
- 접근성(키보드 순서, 대화상자 포커스, 색 대비)은 Accessibility Auditor와 QA 보고서가 다뤘으므로 이 검토에서는 반복하지 않았다.

### A.3 잘 된 점

- 입력 오류가 칸 아래에 글자로 나오고 첫 오류 칸으로 포커스가 간다. 저장 실패에도 입력값이 남는다(G-5).

## C. 우선순위 상위 5개 (합침)

아래는 A장만 보고 정한 잠정안이다. B장이 채워지면 Market Researcher와 함께 다시 순위를 매긴다.

| 순위 | 항목 | 이유 |
|---|---|---|
| 1 | U-01 추천 항목의 가짜 "마지막 교체일 = 오늘" | 핵심 가치(교체 시기 알림)가 첫날부터 틀리고 사용자가 모른다 |
| 2 | U-02 저장 성공·연동 안내 없음 | 차별점(캘린더 연동)의 성공 순간이 보이지 않는다 |
| 3 | U-04 로그인 실패·세션 만료 시 무안내 | 데이터 입력이 반복 실패하는데 해결 길이 없다 |
| 4 | U-16 + U-03 만기일·교체 "알림"이 조용함 | 놓치지 않게 해 주는 제품인데 능동 알림이 없고 탭 이름이 기대를 만든다(BL-4와 연결) |
| 5 | U-06 기록 입력 효율(종류 기본값, 마지막 값 기억) | 가장 자주 하는 동작의 입력 단계를 줄인다(BL-3과 연결) |

차순위 후보는 U-05(교체 완료와 비용 이중 입력), U-07(가득 주유 설명), U-12(차량 선택 유지), U-11(탭 발견성)이다.
